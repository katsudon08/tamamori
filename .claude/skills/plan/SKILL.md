# plan

実装に着手する前に、**ユーザーと議論して計画を固める**ためのスキル。合意できるまでコードは書かない。

## 原則

- 実装に直行しない。計画フェーズ中はファイルを変更しない（plan mode を活用する）。
- 一方的な提示・承認の関係にしない。必ずユーザーの意見を聞き、議論を重ねる。
- リサーチでは誤情報を出さないよう、可能な限り一次情報（公式ドキュメント・該当コードそのもの）を参照する。

## 手順

1. **目的・対象のヒアリング**: 何を・なぜ実装するのかを徹底的に確認する。
2. **to-be の明確化**: 完成状態（受入条件・スコープ・スコープ外）を言語化し、ユーザーと合意する。
3. **現状調査**: 関連コード・既存仕様を読む。外部技術は `WebSearch` / `WebFetch` で公式情報を確認し、出典を添える。
4. **手段の比較**: 実現方法を複数提示し、それぞれのトレードオフ（コスト・リスク・保守性・既存構成との整合）を示してベストを推薦する。
5. **議論と修正**: ユーザーの意見を反映し、過不足が無いと判断できるまで繰り返す。エッジケースや失敗時の挙動を必ず検討する。
6. **実装可否の確認**: 最終計画を提示し（`ExitPlanMode`）、承認を得る。
7. **実行**: 承認後に実装へ移る。

## ルール

- 既存アーキテクチャ・FSD規約（`CLAUDE.md`）との整合を必ず確認する。
- 不確かな情報は断定しない。確認できた一次情報のみを根拠にする。
