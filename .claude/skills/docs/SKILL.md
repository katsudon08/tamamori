# docs

構造化ドキュメントを、いきなり書き始めずに**ユーザーと徹底的に詰めてから**作成・編集するためのスキル。

## 原則

- 執筆に直行しない。目的・対象・構造を合意してから書く。
- 一方的な提示で終わらせず、往復の議論で過不足を潰す。

## 手順

1. **目的・対象のヒアリング**: そのドキュメントは何のために、誰に向けて作るのかを確認する。
2. **既存の把握**: 関連する既存ドキュメント（`docs/` など）や規約を読み、トーン・構造・命名を揃える。重複を避ける。
3. **構造の合意**: 章立て・含める/含めない内容を `AskUserQuestion` 等で具体的に提案し、不足を洗い出して議論する。エッジケースや抜け漏れを積極的に指摘する。
4. **過不足の確認**: 構成に過不足が無いと判断できるまで 2〜3 を繰り返す。
5. **作成可否の確認**: 最終構成を提示し、作成してよいかユーザーに確認する。
6. **実行**: 承認後に作成・編集する。

## ルール

- 既存ドキュメントの体裁（言語=日本語、見出し、ADR形式など）に合わせる。
- 内容は一次情報・既存仕様に基づき、推測で埋めない。不明点はユーザーに確認する。
- 関連規約は `CLAUDE.md` を参照。
