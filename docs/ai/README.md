# docs/ai

`docs/ai` は、AIとの議論・調査・実装計画を一時的に整理するための作業場です。

AIとの会話をそのまま保存するのではなく、実装前に必要な情報を `research.md` や `plan.md` として整理します。

ただし、このディレクトリは正式な設計文書ではありません。未確定の案、却下した案、個人的な理解メモが含まれる可能性があるため、原則としてGit管理しません。

> AIとの議論は作業場に残し、設計判断はチームの資産として残す。

---

## Git管理方針

`docs/ai` 配下の作業メモは原則 `.gitignore` します。

理由は、AIとの議論ログにはノイズ、未確定の仮説、誤った案、個人的なメモ、機密情報が混ざる可能性があるためです。

`.gitignore` には次を追加します。

```gitignore
# AI discussion scratch space
docs/ai/**
!docs/ai/README.md
```

この `README.md` は、運用ルールとテンプレートを共有するためにGit管理します。

---

## 役割分担

| 内容             | 保存先                       |
| -------------- | ------------------------- |
| AIとの調査メモ       | `docs/ai/*-research.md`   |
| 実装前の計画         | `docs/ai/*-plan.md`       |
| アーキテクチャ上の判断    | `docs/adr/`               |
| 技術選定の理由        | `docs/adr/`               |
| 機能全体の設計説明      | `docs/design/`            |
| 今回の変更内容        | PR本文                      |
| タスク単位の補足       | Issueコメント                 |
| AIに継続的に守らせるルール | `CLAUDE.md` / `AGENTS.md` |

`docs/ai` は一時メモの置き場です。
チームで共有すべき判断は、ADR、PR、Issue、`CLAUDE.md`・`AGENTS.md` に昇格します。

---

## 置いてよいもの

* `research.md`
* `plan.md`
* AIとの調査メモ
* 自分の理解確認メモ
* 却下した案の整理
* 一時的なレビュー観点
* AIへの実装依頼文の下書き
* ADR化するか迷っている設計判断の候補

## 置かないもの

* チームで合意した設計判断
* 長期的に残すべき技術選定理由
* 新メンバーが読むべき開発ルール
* PRで説明すべき変更内容
* Issueで共有すべき補足
* APIキー、トークン、認証情報
* 個人情報、顧客情報、機密情報
* AIとの会話全文

## 推奨ファイル名

```txt
<issue-number>-research.md
<issue-number>-plan.md
<feature-name>-research.md
<feature-name>-plan.md
<date>-<topic>-research.md
<date>-<topic>-plan.md
```

例:

```txt

test-logic-research.md
```

# plan.md

## 作成用プロンプト

```txt
あなたは、AI活用開発における実装計画を整理するアシスタントです。

今回の　`research.md`、Issue、要件、関連する議論内容をもとに、`plan.md` を作成してください。

作成にあたっては、`docs/ai/README.md` に定義されている `plan.md` テンプレートに従ってください。

注意点:

- 実装コードはまだ書かない
- `research.md` の内容をそのまま重複させすぎない
- 採用する設計方針を明確にする
- 変更してよい範囲と変更してはいけない範囲を明確にする
- テスト方針とレビュー観点を具体化する
- 共有すべき設計判断はADR化候補として明示する
- 出力はMarkdown形式にする
````

---

## 注意事項

* `docs/ai` の内容をそのままチームの設計判断として扱わない
* 必ず人間が読み、整理し、必要なものだけ昇格する
* AIとの会話全文を貼り付けない
* 機密情報を含めない
* 実装後、不要になったメモは削除してよい
* ADR化した内容と矛盾する古いメモを参照し続けない
* `docs/ai` の内容よりも、ADR、PR、Issue、`CLAUDE.md`、`AGENTS.md` を優先する

---

## 考え方

AIとの議論には、設計判断の材料となる知識が含まれます。

しかし、その議論をそのまま保存しても、チームで再利用できる設計資産にはなりません。重要なのは、AIとの会話を残すことではなく、会話から得られた理解や判断を適切な場所へ整理することです。

`docs/ai` は、そのための一時的な作業場です。

> AIとの議論は作業場に残し、設計判断はチームの資産として残す。
