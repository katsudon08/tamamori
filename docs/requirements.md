# 要件定義書

## プロジェクト概要

- **プロジェクト名**: たま森 (Tamamori)
- **概要**: Slackチャンネルでの活動をもとに盆栽を育てるWebアプリケーション
- **目的**: チームのSlackコミュニケーションを可視化・ゲーミフィケーションし、コミュニケーションの活性化と楽しさを提供する

## ユーザー

- **対象ユーザー**: Slackワークスペースに所属するチームメンバー
- **チーム規模**: 現在6名（増加予定）
- **前提条件**: ユーザーはSlackアカウントを持っている

## 機能要件

### FR-01: Slack連携

- **FR-01-1**: 特定のSlackチャンネルのイベントをリアルタイムで受信する
- **FR-01-2**: メッセージ投稿イベントを検知する
- **FR-01-3**: リアクション追加イベントを検知する
- **FR-01-4**: メッセージ内の感謝キーワード（「ありがとう」「ありがと」「アリガトウ」「感謝」）を検知する
- **FR-01-5**: 監視対象チャンネルを環境変数で設定可能にする
- **FR-01-6**: Slackイベントの重複処理を防ぐ（冪等性の担保）

### FR-02: 盆栽成長システム

- **FR-02-1**: 各ユーザーに1本の盆栽が割り当てられる
- **FR-02-2**: メッセージ投稿により幹が伸び、枝が増える
- **FR-02-3**: リアクション追加により水やりが行われ、葉が生える
- **FR-02-4**: 感謝メッセージにより栄養剤が与えられ、花が咲く
- **FR-02-5**: 盆栽は8段階の成長ステージを持つ（seed → sprout → young → branching → leafy → budding → flowering → full_bloom）
- **FR-02-6**: 成長ステージは3種のアクション（投稿・リアクション・感謝）すべての累計で判定される（バランスの良い活動を報いる）
- **FR-02-7**: 盆栽は枯れることがない
- **FR-02-8**: 成長の閾値はデプロイなしで調整可能にする（DB管理）

### FR-03: 盆栽3D表示

- **FR-03-1**: 盆栽をThree.jsによる3Dグラフィックスで表示する
- **FR-03-2**: 各ユーザーの盆栽は見た目がユニークになる（ユーザーIDベースの決定的生成）
- **FR-03-3**: 盆栽の成長状態に応じて幹の高さ・太さ、枝の数、葉の数、花の数が変化する
- **FR-03-4**: 成長の変化をなめらかなアニメーションで表現する（lerp遷移）
- **FR-03-5**: ステージ昇格時にパーティクルエフェクトで祝福する

### FR-04: 自分の盆栽ページ

- **FR-04-1**: 自分の盆栽を3Dで詳細表示する
- **FR-04-2**: 現在の成長ステージ、累計アクション数を表示する
- **FR-04-3**: 次のステージまでの進捗を表示する

### FR-05: 花壇（ガーデン）ビュー

- **FR-05-1**: チーム全員の盆栽を一覧で3D表示する
- **FR-05-2**: 各盆栽の下にユーザー名を表示する
- **FR-05-3**: 盆栽をクリックすると個別ページに遷移する
- **FR-05-4**: ログイン後のデフォルトページとする

### FR-06: 統計ページ

- **FR-06-1**: 日別のアクティビティ推移を表示する
- **FR-06-2**: アクション種別（メッセージ・リアクション・感謝）の内訳を表示する

### FR-07: 認証

- **FR-07-1**: Slack OAuthによるサインインを提供する
- **FR-07-2**: セッションをCookieで管理する
- **FR-07-3**: 未認証ユーザーはランディングページのみアクセス可能とする

### FR-08: リアルタイム更新

- **FR-08-1**: Slackでアクションが発生したら、開いている画面上の盆栽がリアルタイムに更新される
- **FR-08-2**: 花壇ビューでも他のメンバーの盆栽の変化がリアルタイムに反映される

## 非機能要件

### NFR-01: パフォーマンス

- Slackイベントを受信後、3秒以内にレスポンスを返す（Slack要件）
- フロントエンドの3Dシーンは60fpsを維持する（6本の盆栽表示時）

### NFR-02: 可用性

- Vercelによるホスティングで高可用性を実現する
- Slackイベントの欠損時もカウンターの整合性を保つ（冪等性）

### NFR-03: スケーラビリティ

- 初期6名から20名程度まで対応可能な設計とする
- 花壇ビューの盆栽数増加に対してパフォーマンスを維持する

### NFR-04: セキュリティ

- Slack署名検証によるWebhookエンドポイントの保護
- 環境変数による秘密情報の管理（トークン、シークレット等）
- Supabase Row Level Security の適用

### NFR-05: 保守性

- FSD (Feature-Sliced Design) アーキテクチャによる明確なレイヤー分離
- TypeScriptによる型安全性の確保
- SSoTドキュメントによる設計意思決定の記録

## 用語定義

| 用語               | 説明                                                                         |
| ------------------ | ---------------------------------------------------------------------------- |
| 盆栽 (Bonsai)      | 各ユーザーに1つ割り当てられる仮想の盆栽。Slack活動に応じて成長する           |
| 花壇 (Garden)      | チーム全員の盆栽を一覧表示するビュー                                         |
| 成長ステージ       | 盆栽の成長段階。8段階（seed〜full_bloom）で構成される                        |
| アクション         | Slackで行われた活動。メッセージ投稿、リアクション追加、感謝メッセージの3種類 |
| ビジュアルステート | 盆栽の3D描画に必要なパラメータ群（JSONB形式でDB保存）                        |
